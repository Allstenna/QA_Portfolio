# REST API
|Характеристики|Postman Echo API|GitHub API v3|
|-|-|-|
|Основные эндпоинты и методы|**Методы**: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`<br>**Основные эндпоинты**:<br> - (GET) `/headers` - возврат запрашиваемых заголовков<br> - (GET) `/ip` - возврат IP-адреса<br>- (GET) `/status/{code}` - возврат указанного HTTP-статуса<br>- (GET) `/delay/{seconds}` - искусственная задержка ответов<br>- (GET) `/bytes/{size}` - генерация случайных байтов|- **Методы**: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`<br>**Основные эндпоинты**:<br> - (GET, PATCH) `/users/{username}` - получение информации о пользователе<br> - (GET, PATCH, DELETE) `/repos/{owner}/{repo}` - возврат репозиториев<br>- (GET, POST) `/issues` - возврат списка проблем|
|Форматы запроса и ответа|**Ответы**: JSON<br>**Запрос**: Поддерживаемый (`JSON`, `JS`, `XML`, `HTML`)<br>В ответе сервер возвращает: `args` (query params), `headers`, `url`  и т.д.|**Ответ:** Всегда JSON<br>**Запрос**: Строго JSON<br>Ответ содержит данные ресурса, метаданные (линки, статусы) и заголовки лимитов.|
|Особенности авторизации и версии API|**Авторизация**: отсутствует для основных эндпоинтов<br>Есть спец. эндпоинты для тестирования авторизации (заполненные поля `username` и `password`):<br>- `/basic-auth` - требуется заголовок `Basic-Auth`<br>- `digest-auth` - требуется заголовок `Digest-Auth`<br>**Версионирование**: Отсутствует. Сервис стабилен и не имеет версий|**Авторизация:** OAuth 2.0 или Personal Access Tokens (PAT)<br>(`Authorization: Bearer <TOKEN>`)<br>**Версионирование**: Через заголовок Accept (`application/vnd.github.v3+json`)|
|Отличия в подходах к дизайну и структуре|**1.** Данные не сохраняются. POST-запрос не создает ресурс на сервере.<br>**2.** Главная цель — помочь разработчику увидеть, что именно ушло в запросе.<br>**3.** Нет лимитов (или они очень мягкие), нет сложных кодов ошибок (почти всегда 200 OK)<br>**4.** Нет жесткой валидации входящих данных|**1.** Запросы меняют состояние сервера (создание репозитория, изменение профиля)<br>**2.** Строгое следование принципам REST (ресурсы, методы)<br>**3.** Строгое ограничение запросов, сложная система ошибок (403, 404, 422)<br>**4.** Строгая проверка данных через схему (например, имя репозитория не может быть пустым)|
