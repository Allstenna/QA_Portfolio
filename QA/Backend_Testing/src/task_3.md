# Базы данных
***Сервис***: [VK.com](https://vk.com)
***Гипотеза***: **Гибридный подход**
Сервис VK представляет собой комплекс интегрированных приложений, предназначенных для выполнения различных задач и функций. Процесс создания постов осуществляется через специализированную форму, которая отправляет данные на сервер, где они заносятся в реляционную базу данных (БД). Таблица "posts" включает поля "id", "title", "description", "created_at", "author" (информация об авторе может быть взята из таблицы "users") и другие. Посты также сопровождаются изображениями, которые на мобильных устройствах отображаются с использованием слайдера (ограничение на количество выводимых изображений осуществляется посредством SQL-запросов). Аналогичный механизм применяется и при создании пользовательских профилей.<br>
Для обеспечения отображения ленты постов используется нереляционная база данных. Такая структура данных позволяет осуществлять просмотр публикаций в режиме реального времени без значительных задержек и обеспечивает возможность горизонтального масштабирования в случае увеличения объема данных. Нереляционные базы данных также могут быть задействованы для отображения метрик публикаций при запуске рекламных кампаний на платформе. Такие базы данных способны хранить большие объемы информации за выбранный временной период, включая количество откликов, просмотров и трафика.

***Функции***:
1. Лента постов<br>
- связи между пользователями (друзья, подписки, блокировки)
- посты, репосты, лайки, комментарии
- события активности (онлайн-статус, просмотры
- персонализированные настройки ленты<br>
**Тип БД**: Нереляционная<br>
**Причина**: просмотр ленты пользователем должно происходить в реальном времени и без сильных задержек. Предложение добавить друзей должно браться из большого кол-ва данных (например, город проживания, друзья друзей).

2. Мессенджер и чаты<br>
- текстовые сообщения, медиа-вложения
- данные диалогов (участники, время создания, статусы)
- статусы доставки/прочтения, реакции сообщений
- история переписки<br>
**Тип БД**: Нереляционная<br>
**Причина**: поток сообщений огромный и постоянный. Статусы сообщений должны обновляться в реальном времени, также как и удаление сообщений.

3. Хранение медиа (фото, видео, аудио)<br>
- файлы: изображения, видео, аудио
- данные: автор, альбом, теги, права доступа
- превью и хеши файлов
- история переписки<br>
**Тип БД**: Нереляционная<br>
**Причина**: хранилища для больших бинарных объектов (видео). Возможность подключения транскрипции для аудио.

4. Профили и аутентификация<br>
-   учетные данные: email/телефон, хеши паролей, ключи
-   профиль: имя, аватар, дата рождения, город, образование
-   настройки приватности, уведомления, сессии
-   журналы входа (логи) и безопасности<br>
**Тип БД**: Реляционная<br>
**Причина**: строгое соблюдение правил аутентификации через пароли и/или ключи. Смена пароля должна быть атомарна для каждого пользователя с ее последующей проверкой.
